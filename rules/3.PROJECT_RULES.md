# Project Rules

These rules are the source of truth for this frontend project. Keep them aligned with the actual source tree, `package.json`, and tool configuration.

## Product Context

This repository is a realtime chat frontend. Optimize structure and behavior for authentication, conversation lists, direct/group rooms, message rendering, message composition, optimistic sends, read receipts, typing state, presence, reconnects, notifications, and user profile/settings.

## Current Stack

- React 19 with TypeScript.
- Rsbuild and Rspack for dev/build.
- React Router for SPA routing.
- Tailwind CSS v4 and CSS design tokens.
- shadcn/ui-style primitives in `src/components/ui`.
- React Hook Form and Zod for forms and validation.
- Axios for HTTP services.
- TanStack Query for server state.
- Zustand for small global client state.
- `@stomp/stompjs` for realtime messaging.
- Sonner for toasts.
- lucide-react for icons.
- Biome for linting and formatting.
- Bun for scripts and dependency management.

## Commands

Use scripts from `package.json`. On Windows PowerShell, use `bun.cmd` when the Bun shim is blocked.

```bash
bun.cmd run check
bun.cmd run typecheck
bun.cmd run build
```

Run `check` and `typecheck` before finishing meaningful source changes. Run `build` for UI, config, route, dependency, or build-related changes. Run test scripts when they exist or when you add them. Use `:fix` scripts only when you intentionally want tools to write changes.

## Source Structure

All app code belongs under `src`.

```text
src/
  app.tsx
  index.tsx
  globals.css

  components/
    ui/                  # raw shadcn/ui primitives
    shared/              # app-custom reusable UI

  config/                # env, constants, routes, storage keys, socket events
  pages/                 # thin route page files
  features/              # bounded product features
  hooks/
    api/                 # reusable TanStack Query API hooks
  libs/                  # configured clients and library integrations
  providers/             # app-level providers and route guards
  services/              # HTTP and socket service functions
  stores/                # global Zustand stores
  types/                 # app-wide shared contracts
  utils/                 # reusable pure utilities, including cn
```

## Architectural Principles

- Keep route files thin. Pages render feature templates and route-level composition only.
- Keep product behavior in bounded feature modules.
- Keep presentational components prop-driven. Move orchestration to feature hooks, templates, or providers.
- Keep HTTP/STOMP protocol details in services/libs, not in components.
- Keep server state in TanStack Query. Do not duplicate server cache into Zustand.
- Use Zustand only for small client state that crosses route or feature boundaries.
- Prefer existing local patterns over new abstractions.
- Add abstractions only when they remove real duplication or clarify an existing boundary.
- Avoid broad refactors while implementing a focused feature.

## Import Boundaries

- `pages` may import from `features`, app providers, `config`, and shared components.
- `features` may import from `components/ui`, `components/shared`, `hooks`, `services`, `stores`, `types`, `utils`, `config`, and `libs`.
- Cross-feature imports are normally avoided. A route-shell feature may compose feature templates/components when it owns the screen layout; otherwise promote shared code to `components/shared`, `hooks`, `types`, or `utils`.
- `components/shared` may import from `components/ui`, `hooks`, `types`, `utils`, and `config`; it must not import feature-private code.
- `components/ui` should import only low-level utilities and required UI dependencies.
- `hooks/api` may import from `services`, `types`, `utils`, `config`, and query-key helpers.
- `services` may import from `libs`, `types`, `utils`, and `config`.
- Avoid imports from `pages` anywhere else.

## TypeScript And Tooling

- Keep TypeScript strict. Do not loosen `tsconfig.json` to make errors disappear.
- `verbatimModuleSyntax` must stay enabled for Rsbuild/SWC-safe type-only imports.
- Prefer named exports for app code. Existing default exports may remain until a scoped refactor touches them.
- Prefer type-only imports and exports for types.
- Avoid `any`. If unavoidable, keep it local, document why, and never expose it through public types.
- Do not add new lint disables unless the reason is local, explicit, and temporary. Existing global lint exemptions should be tightened in a dedicated cleanup pass.

## Dependency Rules

- Use installed packages before adding new ones.
- Do not add another library for a capability already covered by the stack.
- Add dependencies with `bun add` or `bun add -d` so `bun.lock` stays correct.
- Use lucide-react icons for action icons.
- Use `cn` from `@/utils/cn` for conditional Tailwind classes.
- Research official docs before adding shadcn/ui primitives, Rsbuild plugins, reusable hook utilities, or TanStack Query patterns that are not already used locally.

## Before Finishing

1. Confirm code is in the right layer.
2. Check existing `ui`, `shared`, `features`, `hooks`, `services`, `types`, `utils`, and `libs` before adding duplicates.
3. Check for unnecessary `useEffect`, `useState`, `useMemo`, and `useCallback`.
4. Check query cache invalidation/update behavior when touching server state.
5. Check socket listeners, reconnects, and cleanup when touching realtime code.
6. Check loading, empty, error, disabled, and success states for user-facing flows.
7. Run verification commands or state why they were not run.
