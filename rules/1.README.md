# Rules README

This folder contains the coding rules for the realtime chat frontend.

`AGENTS.md` is the root entrypoint. It tells agents which rule files to read before editing a layer.

## Files

- `PROJECT_RULES.md` - project-wide stack, architecture, import boundaries, dependency, and verification rules.
- `naming.md` - naming rules for folders, files, exports, variables, hooks, types, constants, and chat fields.
- `src.md` - rules for all source files.
- `pages.md` - thin route page rules.
- `features.md` - feature module structure and ownership rules.
- `components.md` - shared component, UI state, styling, and accessibility rules.
- `components-ui.md` - raw shadcn/ui primitive rules.
- `hooks.md` - reusable hook and API hook rules.
- `data-fetching.md` - TanStack Query, cache, optimistic update, and server-state rules.
- `services.md` - HTTP and socket service rules.
- `realtime.md` - STOMP/WebSocket lifecycle, subscription, event, message, presence, and typing rules.
- `config.md` - env, constants, routes, socket events, and app config rules.
- `security.md` - env safety, tokens, sensitive data, storage, dependencies, and user-generated content rules.
- `stores.md` - global Zustand store rules.
- `types.md` - shared type rules.
- `utils.md` - reusable utility rules.
- `libs.md` - third-party client and integration rules.
- `testing.md` - test coverage and verification rules.
- `code_review.md` - review checklist before final response.
- `prompts/feature-development.prompt.md` - reusable prompt template for future feature work.

## Maintenance

- Keep these rules aligned with the real project structure and `package.json`.
- Keep rule files focused. Prefer adding a scoped rule to expanding `PROJECT_RULES.md`.
- Do not mention tools that are not installed unless the rule explicitly says when/how to add them.
- Update this folder when architecture conventions change.
